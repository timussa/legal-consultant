# Подключение моделей

## Настроенный локальный профиль

На рабочем компьютере .env использует Ollama по адресу http://localhost:11434/v1. Генерация и самопроверка выполняются моделью legal-assistant-local на основе qwen3.5:9b. Эмбеддинги выполняет bge-m3. Реранкер отключён. API-ключ имеет техническое значение ollama.

Профиль воспроизводится через .env.ollama.example и ollama/Modelfile. В модели задан контекст 16384 токена. Тайм-аут запросов увеличен до 180 секунд для первой загрузки модели. CHAT_REASONING_EFFORT=none отключает reasoning в совместимом API Ollama. Первый пробный запуск моделей подтвердил размещение обеих на GPU при расходе около 8,7 ГБ видеопамяти.

Этот профиль используется для локальной разработки. На платформе модели и настройки доступа подставляются организаторами.

На автоматической проверке используются DeepSeek V4.1 Flash, BAAI/bge-m3 и необязательный Qwen3 Reranker 8B. Адрес единого прокси, служебный ключ и имена моделей передаются платформой через окружение. В ZIP включается код, личные ключи в него не входят.

По вопросам 28, 30, 33 вебинара локальные ключи организаторов не выдаются. Для финальной проверки жюри самостоятельно получает ключ указанного в инструкции сервиса. Локальная разработка требует собственных учётных записей провайдеров.

## Первый локальный запуск

Скопируйте .env.local.example в .env. При первом запуске достаточно LLM_API_KEY от DeepSeek. В этом профиле поиск работает через BM25. После добавления BGE включите ENABLE_EMBEDDINGS=true.

1. Зарегистрируйтесь на https://platform.deepseek.com и создайте ключ в разделе API Keys. При необходимости пополните API-баланс в своём аккаунте.
2. Впишите ключ в LLM_API_KEY файла .env. Остальные параметры генерации в шаблоне уже заполнены.
3. Выполните python scripts/check_models.py, затем python scripts/evaluate.py.
4. Для веб-интерфейса выполните docker compose up --build и откройте http://localhost:8080.

Официальный base URL — https://api.deepseek.com. Имя модели — deepseek-flash. Согласно текущей документации это DeepSeek V4.1 Flash. Конкретная ревизия и настройки сервиса могут отличаться от прокси хакатона, поэтому окончательное качество проверяется сабмитом.

Документация https://api-docs.deepseek.com/en/

Шаблон включает JSON Output и отключает thinking для первого прогона с MAX_TOKENS=3000. Эти настройки задаются только локальным профилем. Для испытания reasoning можно включить CHAT_THINKING=enabled и увеличить MAX_TOKENS с учётом общего времени запуска. В прокси хакатона дополнительные параметры по умолчанию не отправляются.

Документация JSON https://api-docs.deepseek.com/guides/json_mode/
Документация thinking https://api-docs.deepseek.com/guides/thinking_mode/

## Эмбеддинги BGE-M3

DeepInfra предоставляет BAAI/bge-m3 через OpenAI-совместимый endpoint.

1. Зарегистрируйтесь на https://deepinfra.com и создайте API key в Dashboard. Подключите оплату или доступный баланс по условиям аккаунта.
2. Впишите его в EMBEDDER_API_KEY.
3. Оставьте EMBEDDER_BASE_URL=https://api.deepinfra.com/v1/openai и EMB_MODEL=BAAI/bge-m3.
4. Установите ENABLE_EMBEDDINGS=true и повторите проверку подключений.

Документация модели https://deepinfra.com/BAAI/bge-m3/api
Получение ключа https://docs.deepinfra.com/quickstart

При смене модели эмбеддингов нужен новый индекс. Имя EMB_MODEL на платформе определяется её окружением. Заранее подготовленный индекс применится только при совпадении отпечатка. Начальный API-тест проверяет форму векторов, а оценочный прогон нужен для проверки поиска по-русски.

## Реранкер Qwen3 8B

SiliconFlow документирует модель Qwen/Qwen3-Reranker-8B на endpoint /v1/rerank.

1. Создайте аккаунт на https://cloud.siliconflow.com.
2. В разделе API Keys нажмите Create API Key. Проверьте доступность модели и условия оплаты в Models своего аккаунта.
3. Впишите ключ в RERANKER_API_KEY и выставьте RERANKER_MODEL=Qwen/Qwen3-Reranker-8B.
4. Оставьте RERANKER_BASE_URL=https://api.siliconflow.com/v1 и повторите проверку подключений.

Получение ключа https://docs.siliconflow.com/en/userguide/quickstart
Документация реранкера https://docs.siliconflow.com/en/api-reference/rerank/create-rerank

Реранкер опционален по условиям кейса. Пустой RERANKER_MODEL отключает его. Доступность сервисов, способы оплаты и региональные ограничения зависят от аккаунта и проверяются при регистрации.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| LLM_BASE_URL, LLM_API_KEY, LLM_MODEL | Генерация и семантическая проверка ответа |
| EMBEDDER_BASE_URL, EMBEDDER_API_KEY, EMB_MODEL | Эмбеддинги документов и запросов |
| RERANKER_BASE_URL, RERANKER_API_KEY, RERANKER_MODEL | Реранжирование |
| CHAT_JSON_MODE | Отправлять response_format=json_object |
| CHAT_THINKING | enabled или disabled, пустое значение оставляет настройки сервиса |
| ENABLE_EMBEDDINGS | Использовать векторный поиск |

Когда отдельный URL не задан, сервис использует общий адрес и ключ LLM. При отдельном URL требуется ключ соответствующего провайдера. Ключ генерации не пересылается автоматически другому провайдеру.

## Действия владельца проекта

Учётные записи, вход, подтверждение email/телефона, выбор способа оплаты и расходов требуют участия владельца. Затем ключи сохраняются локально в .env. Их не нужно присылать в чат или публиковать в Git.

Docker Desktop необходим для проверки Docker-сценария. При необходимости его установка и перезапуск компьютера выполняются владельцем. Проверка Docker-конфигурации ещё предстоит.

Отправка ZIP на платформу требует доступа участника к аккаунту команды. Учитывается общий лимит 5 попыток в день. Пример результатов реальных моделей и окончательная презентация готовятся после доступного оценочного прогона.

## Результаты локальной проверки

В полном прогоне 18 демонстрационных вопросов зарегистрированы ответы и ошибки самопроверки. После повторной проверки исправленных сценариев ответ возвращается для 16 вопросов. Вопросы 3 и 13 остаются отклонёнными проверками, поскольку локальная Qwen добавляет неподтверждённые номера документов или основания обработки данных. Эти результаты сохранены в output/local_validation.json. Факт возврата ответа не является оценкой его юридической корректности. Нужна ручная оценка текста, особенно выводов и исключений.

Полный прогон до повторных исправлений занял около 214 секунд. Во время нагрузки Qwen и BGE находились на GPU, использовалось примерно 8,7 ГБ VRAM. Для сопоставимого нового прогона выполните python scripts/evaluate.py --output-dir output/ollama-new.
